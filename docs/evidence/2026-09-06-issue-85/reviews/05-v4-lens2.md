## Findings

1. **Attack 1 - §2 / §3 / §7 S6. The predicate language has no atom that compares two positions of one path, and `0001`'s second job needs one.** §2: *"Nothing else in the vocabulary names a set."* §3 grounds paths on `0100`: *"a statement about relations across obligations."* §7 S6 claims *which obligations, across courses, require the same concept* is `START(obligation) · MOVE(requires) · MOVE(requires, pointed-by)`. That chain returns, for every obligation A, the reflexive path *A - c - A* and every same-course pair; `P ::= <field> <comparison> <value>` takes a literal, so neither `id ≠ start.id` nor `course ≠ start.course` is expressible. The cross-course set arrives only as one call per course (`FILTER(course = c) … FILTER(course ≠ c)`, five returns) - which is exactly what §4's premise forbids and what the `MOVE with Q` row treats as "returns a superset", i.e. not the set. A judgment the draft itself names as a must is served by no chain in one return; §2's completeness claim is false. **blocking**

2. **Attack 1/2 - §3 and §8. The ruled output type makes `REPEAT` non-finite, and §8 misdescribes `closure`.** §3: *"Deduplication is by path, so a member reached over four links … is four paths."* `0012` rules only `part-of` a DAG; `requires` (concept → concept) and `builds-on` are not ruled acyclic. On a two-node `requires` cycle, `START(ref) · REPEAT(MOVE(requires))` has unboundedly many distinct paths, so "the set of paths" does not exist. §8 then rules *"`closure` is `REPEAT`, signature for signature"* - but `CONTEXT.md` `closure` is *"The set of nodes reachable from one node"* and `0013` the same: node set, not path set. The signatures differ and the draft says they do not. **blocking**

3. **Attack 4 - §3, last paragraph.** *"routing's boundary is its range, and *not in the store* is a separate holder's answer."* `CONTEXT.md` **holder**: *"today the coordinator alone, and what it answers from is the skeleton and the store"*, with *"treating the skeleton and the store as holders in their own right"* on the Avoid list; `0081` the same. The store is not a holder, separate or otherwise, and a ruled section says it is. (#66's comment does say "ring 0, the skeleton and the store remain the only holders", but the glossary is the term's authority and it says the opposite.) **blocking**

4. **Attack 4 - §5 deviation table, row 10.** *"`applies` "feeds closure and is never rendered" (`CONTEXT.md`); a path over it is a result and is not shown as a block's neighbour."* The glossary says *never rendered*, full stop; the draft narrows that to *not shown as a block's neighbour* and rules that a resolve may return an `applies` path to the coordinator, which renders it. That is an amendment to the `applies` entry, and §9.6 lists `routing`, `path`, `ring 0`, `the walk`, `closure`, `the line` - not `applies`. **blocking**

5. **Attack 4 - §9.3 against §3.** §9.3: *"`0004`'s size gate is unchanged: what must stay bounded is the cost of expanding a block, and a path carries no block."* `0004`'s first sentence: *"total size is the wrong quantity to budget."* §3: *"a resolve over a whole kind may be too wide to hold"* - `START(K)` is O(kind), `REPEAT` is closure-sized. The draft introduces an operation whose affordability is a function of graph size and simultaneously leaves standing a record that says graph size is the wrong quantity; the amendment touches only the one-level-one-call sentence. **blocking**

6. **Attack 4 - §6.** *"`0021`'s time projection is another such standing result"* - where *such* is *"held resident by policy"* from the paragraph's first sentence. `0021` says *"a separate projection over the skeleton the way ring 0 is"* and nothing about residency. Either the record is misdescribed, or the draft decides that a second projection is resident, which #82 refused for ring 0's widening and which §10 does not list. **blocking**

7. **Attack 4 - §4 wildcard row against §10 and §1.** §4 rules the wildcard crossing is *"exposed through `look_at`, not as its own verb"* (Billy's, treated as ruled). §10 says the draft does not decide *"whether the two starts, or any step, are one surface verb"* and #84's *Destination* puts the grammar later - so §10 disclaims a decision the comment records. §1 in the same breath: *"`look_at(id)`, a read, not routing"*, while §4 puts a routing step inside it and §8 calls `0084`'s composition *"resolve entering through fetch."* The ruling stands; the draft's scope statement and its own definition of fetch contradict it. **blocking** by the threshold's letter (a decision the draft says it does not make); the fix is §10 and §1 wording.

8. **Attack 2 - §4 table, two rows fail their own "without it" cell because "step" is undefined across the four `MOVE` rows.** (a) *field comparison*: judgment *which obligations are in course C*; cell says *"`START` names only a kind; `course` is a field"* - but `START(ref C) · MOVE(course, pointed-by)` (the `MOVE(field, D)` row, an *other* step) produces the set. Verdict survives on `due < d`, which no crossing reaches. (b) *`MOVE(L, D)`*: judgment *which concepts does this obligation require, and by which link*; cell says *"no predicate reaches a link's other end"* - but the wildcard row is an *other* step, and `START(ref A) · MOVE() · FILTER(kind = concept)` produces the identical set under `0012` (obligation → concept is `requires` alone), with the link on the path. Also `kind` is a link field (`0017`), so `Q` alone can pin `L`. Verdict survives on direction from a `START(K)` start. **repair**

9. **Attack 2 - §4 `exists` row, second judgment.** *which concepts are required by both A and B* is served without `exists`: `START(ref A) · MOVE(requires) · MOVE(requires, pointed-by) · FILTER(id = B)` returns paths *A - c - B* whose middles are exactly that set. The first judgment (`0003`'s complement) carries the row alone. **repair**

10. **Attack 2 - §4 `START(ref)` row.** Verdict cell reads *"a spelling; the grammar keeps or drops it"*; the test is an *iff* and the cell's own evidence makes it **out** as a step, while §2 lists it in *"The domain, as chain steps"* and says *"both are kept."* Say which it is. **repair**

11. **Attack 4 - §4 `MOVE(field, D)` row, instance cell.** `0084`'s `obligations.list(course)` is *"a service read over an indexed field"* for one named course - by §2's own extensional identity that is `FILTER(course = C)`, and the same instance already sits in the field-comparison row. It is not an instance of crossing from a *computed* set, which is the row's whole argument. **repair**

12. **Attack 4 - §2.** *"A ring 0 row carries an id (`0025`)"*. `0025` speaks of reads that return records; `0038`'s field set has no `id`; what puts an `id` on a line is `0082` (*"`id` and `kind` are attributes because they address"*) and `0061`. Cite those or drop the claim. **repair**

13. **Attack 4 - §6.** *"a standing result is held by policy - which is what `0019` already says ring 0 is."* `0019` says *"residency is an access policy over obligation nodes' fields"* - a policy over fields, not a result of anything. **repair**

14. **Attack 4 - §7 S3 and §8.** S3: *"returning `0089`'s delta"* - `0089`'s title is *"the refresh returns whole lines rather than a delta"* and its body *"Not a field-level delta."* §8: *"'the read side is two verbs' … true of fetch, and silent on resolve"* - the draft's own S3 makes `refresh()` a frozen resolve, so the sentence is not silent on resolve, it names one. **repair**

15. **Attack 4 - §2.** *"An address is a handle the query accepts: today a node's `id` and an edge's `id` (`0096`, `0097`)."* `0096` gives the edge an id so *"`attach` and `detach` have something to name"* (write side); `0089`: *"`look_at(id)` reads one node."* `0097`'s general rule does support the claim; cite it against `0089`'s sentence rather than leaving the tension unnamed, since paths are ruled to end at an address. **repair**

16. **Attack 1 - §3 well-definedness.** *"A path is the chain a member arrived by - node, link, node, …"* A `MOVE(field, D)` crossing has no link record, so what the path carries at that position is unstated; S7 depends on it. **repair**

17. **Attack 4 - §9.2.** *"the interpreter for §2's steps over the adjacency index is itself hand-writable"* names the persistence tier's structure (`0059`) as the interpreter's substrate while §10 says *"which tier holds routing's interpreter"* is undecided; and `0062`'s struck ground was a measurement (52 KB, 0.27 ms, three queries), the replacement is an assertion with no instance. 18. **Attack 4 - §9.4 against #85's body.** The body: #16's two tests *"belong in this answer rather than waking #16 separately."* The draft rules one and returns the other to #16. Not a record contradiction, but the comment should say it departs from the body's instruction and why. **repair**

19. **Attack 3 - §2 / §4 direction.** §2 enumerates candidates by the read's target (kind, Ref, field, link, field-crossing) and §4 finds a judgment per candidate - §7 admits *"S3-S7 are agent-constructed to exercise the rest."* That is the axis #84 declares against (*"never by the read's target"*), and the *must* column is sourced only where an instance record carries it (`0003`, `CONTEXT.md`'s opening); rows 2, 5, 7 and 8 assert a must with no source. The verdicts do not change if each must is tied to `0001` / `CONTEXT.md` or marked #86's, so **repair** - but the record §9.6 proposes should not say the domain was *derived* from the vocabulary; it was bounded by it.
