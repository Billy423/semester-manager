## Findings

**1. [Attack 1] §3 "Routing returns a set of addresses ... The set is unordered" / §2 "a member reached by `MOVE` over a link also carries the link it was crossed by" - a judgment over relations across obligations arrives in no single return.** `0100` grounds the defect of "one row per source row, with the relations between rows left to the reader's eye" on `0001`'s second job, "a statement about relations across obligations rather than about any one of them", and #82's ruling routes "relations requiring the skeleton" to `0021`'s "separate projection over the skeleton the way ring 0 is". §6 then makes a projection "a result rather than a persisted thing", i.e. a flat set. Concrete judgment: *which obligations, across courses, require the same concept, and which concept*. `START(obligation) · MOVE(requires, points-at) · MOVE(requires, pointed-by)` returns a deduplicated set `{A, B, D}` in which the pairing is gone; even the one-hop grouping *which obligations require each concept* is lost, because a concept required by A and B is one member and "carries the link it was crossed by" is singular. Recovering the relation is one call per obligation, which is the growth the ruled premise (§4) forbids. No chain of §2 returns a relation; the output type has no position for one. `blocking`

**2. [Attack 1 / 2] §2 "a member reached by `MOVE` over a link also carries the link it was crossed by" - ill-defined, and §4's extension test depends on it.** `0017`: *"one deck cites the textbook four times at four different sections, and those are four links, not one."* A member reached over several links (that case, or any `START(K) · MOVE` with fan-in) has no single "link it was crossed by", and a *set* of addresses cannot carry more than one per member. Either the output is a set of (link, address) pairs, in which case §3's "set of addresses" and "unordered" are wrong and two chains over the same addresses are not "one operation" to the test, or the link is dropped, in which case `MOVE` with `Q` and `0012`'s `role` cannot be read off a result. §4 says "Two spellings of the same set are one operation to it" without saying whether the set is of addresses or of pairs. Ambiguous on a ruled output type. `blocking`

**3. [Attack 2] §4 row `MOVE(L, D)`, cell "`exists` tests, it does not return the other end" - false, and the table applies the test under two incompatible readings.** `START(concept) · FILTER(exists(MOVE(requires, pointed-by) · FILTER(id = A)))` returns exactly the concepts A requires, i.e. the other end, and `START(obligation) · FILTER(P) · MOVE(requires)` is `START(concept) · FILTER(exists(MOVE(requires, pointed-by) · FILTER(P)))` in general. Under the draft's own stated limit ("The test admits by extension"), top-level `MOVE(L, D)` is a spelling of `START(K) · FILTER(exists(...))` in exactly the way `START(ref)` is a spelling of `START(K) · FILTER(id = X)`, yet the table gives `START(ref)` "a spelling" and `MOVE(L, D)` "in". The test's "the other steps and atoms" does not say whether a step used inside `exists` counts as present; the two verdicts each assume a different answer. Fixing the cell changes a verdict. `blocking`

**4. The step survives only for crossing from a *computed* set of courses, which is S7, and §7 says S3-S7 "are not evidence for it". The row is ruled "in" unconditionally where `Q` and `REPEAT` are ruled "in, if"; the test as run supports only the conditional form. `blocking`

**5.
