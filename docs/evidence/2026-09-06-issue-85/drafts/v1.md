**What this comment is.** The definition of routing, its inputs and output, the necessity test that generates the read side's capability list, and the HNSW verdict - the four things the body asked for - plus what the definition makes ring 0, and the amendments it forces. The gap table in §7 is a **draft** input to #86, #87 and #88 and is labelled so. Everything else here is ruled.

**How it was reached.** By grilling, from routing's responsibility outward, and not from ring 0's current shape inward - three earlier framings were rejected in the session for reasoning from the artifact back to the purpose (`0100`'s diagnosis of `0038`, repeated on gaps, on renders and on a starting position). Nothing below was derived from a field table, a scenario's step list or a gap list.

### 1. Definition

**Routing is the resolving half of the query: a system-held function from an intent to the addresses that satisfy it.**

```
routing : intent -> [address]
```

The query has two halves. **Fetch** takes an address and returns its render - `look_at(id)`, a read, not routing. **Resolve** takes an intent the caller can state in the surface's own vocabulary and returns the addresses that satisfy it. Routing is resolve.

**Who holds what.** The system holds routing. The coordinator holds two things: the intent it forms, and one routing result resident by policy - ring 0 (§6). A dispatch target holds nothing (`CONTEXT.md`, *holder*). No new holder is introduced; #66 is not woken.

**Spontaneity, restated as a mechanism.** Routing is not prompt-driven, and *unprompted* does not mean *without the owner*: it means **the intent must be formable from what the current render exposes**. The schema vocabulary reaches the coordinator in-band - `0098` spells names back, `0092`'s `has-more` lists a node's link kinds, `0096`'s `<edge>` carries `type` and `direction` - so `look_at` is this system's introspection, and the coordinator learns what it can ask by looking. It never needs the schema out of band.

**What routing is not.** Not a lookup from a need to a location (that starts from a supplied need); not a search (`0046`); not the delivery of an answer (that is fetch); not a judgment of importance (a judgment is made *with* capabilities and can never be an element of a capability list); not a property of renders (what a render must carry so that an intent can be formed from it is #82's, downstream of this). Mechanistic reachability - that a path exists in the skeleton - is a property of the schema, already satisfied (`0012`'s table reaches all three of `CONTEXT.md`'s answerability targets), deliberately not universal (two unrelated nodes may coexist), and not routing's.

### 2. Inputs - deliverable 1

**Routing's input is one intent, stated in the skeleton's structural vocabulary**: kind, link kind, direction, field = value. Not *ring 0 plus the skeleton index* as the body guessed - that is what the coordinator sees, not what routing consumes. An intent by content (*things about X*) is not in the domain: `0046` routes it to dispatch, and `0001` names precise question-answering as not the job. That is a deliberate non-service, not a gap.

**The domain is a traversal algebra, not an enum.** Four generators, all already present in landed records, closed under composition:

| generator | parameters | landed as |
|---|---|---|
| anchored one-hop | (source id, link kind, direction) | `0046`'s walk; rendered by `0096` |
| unanchored filter | (kind, field = value) | `0084`'s `obligations.list(course)` |
| unanchored absence | (kind, link kind, direction) | `0003`'s `nodes_without`, signature for signature |
| anchored transitive | (source id, link kind) | `0013`'s `closure` |

Two axes: **anchored or not** (from a node, or a predicate over a layer), **one step or transitive**. Both anchored and unanchored are in the domain: the coordinator's first intent when unprompted is formed from ring 0, which is a set of lines and not a node, so it is necessarily unanchored; and `nodes_without` is unanchored and the test must generate it. Transitive is in the domain on `0043`'s ground, not on `0013`'s existence (§4).

**Composition is one call.** `0043` drops what is fetched, so the coordinator cannot hold an intermediate result between calls. A judgment ranging over a composed set - *the concepts required by band-A obligations that no artifact covers* - is therefore not expensive under an enum domain; it is impossible. `0060` arrives at the same place from the grammar side. **The syntax of the composition is the query grammar, a later decision (#84 Notes); what is ruled here is that the domain composes.**

**No wildcards.** Routing requires a fully specified intent. `routing(id, *, *)` would return what `look_at(id)`'s `<neighbours>` already returns, one fact under two names (`0024`); discovery is fetch's job. From ring 0, where there is no node to fetch, band A's `has-more` is the discovery channel.

**An anchored intent may be anchored on an edge.** `0096` gives an edge an `id` and `0097` makes any tag with an `id` addressable, so an edge is a legal source. Whether an edge's id shares the node id space is stated nowhere - `0025`'s one space is *"shared by every kind that can be a link endpoint"*, which an edge is not - and #80 listed this as an outstanding confirmation that PR #81's landing did not answer. It bears on whether the resolve call needs to know which it was handed. It belongs with the grammar and is pointed at from here, not ruled.

### 3. Output - deliverable 2

**Routing returns lines** - for an unanchored intent, the line of each node; for an anchored one, each `<edge>` carrying the target's line inside it (`0096`). Not bare ids: `0089` rejected an id-only signal because an id *"says nothing about the record it names"*, and `CONTEXT.md`'s *line* is exactly *"what decides whether it is worth that call"*. **Resolve returns lines; fetch returns a block** - this is the mechanism behind the line/block distinction the glossary already draws.

**The body's trichotomy is not three alternatives.** The output is lines. *Dispatch* is the form `0039` selects when the lines are unaffordable to observe symmetrically. *Layer entry* is an intent that ranges over a different layer, not a different kind of output. Nothing routing returns is an entry point into anything.

**An empty result names its boundary.** `0081`: routing returning `[]` carries what it ranged over - the layer, the source, the link kind.

**Cost.** Anchored: O(degree) (`0046`). Unanchored: O(layer). Whether the result can be observed at all is `0039`'s decision over the judgment's set, not routing's. Ring 0's roughly-55 is one such `0039` judgment held resident; it is not a bound on routing, and it carries `0038`'s scope clause and the fall26 caveat.

### 4. The necessity test - deliverable 3

The domain is an algebra, so the test ranges over **generators**, not over verbs.

> **A generator belongs in routing's domain if and only if there is a judgment the coordinator must make whose set (a) no composition of the other generators resolves, and (b) `0043` bars the coordinator from assembling by repeated calls.**

Clause (b) is where this system differs from a graph database inside the test itself: a database's caller can assemble; this one's cannot. Without (b) the transitive generator falls out - transitively is mathematically a composition of one-hops - and it is `0043`, not the algebra, that makes it necessary.

**The test generates all four:**

| generator | the judgment | without it |
|---|---|---|
| anchored one-hop | which of X's neighbours are worth a look | `0016`: relations are records, not fields; a filter cannot see an edge |
| unanchored filter | which obligations are in course C | `0029`: course is a field, not an edge; no hop from a course reaches one - `0084`'s forcing case, reproduced |
| unanchored absence | which concepts have no covering artifact | a filter cannot see links, a hop cannot see what is absent; `0081` requires the negative to be stateable |
| anchored transitive | a judgment over a closure (`0039`'s set S) | N one-hops, and `0043` bars holding them |

**And excludes what it should:**

| candidate | the judgment | who serves it | excluded because |
|---|---|---|---|
| wildcard `(id, *, *)` | what exits does X have | `look_at`'s `<neighbours>` | fails (a) |
| by content | what is about X | dispatch, by `0046` | not a judgment over the skeleton |

**The `nodes_without` check #84's charting comment set is passed** - it is the absence generator, and it fell out of `0081` rather than being placed. **`closure` is the transitive generator.** Whether either needs to exist as a *separately named* operation is #88's ruling; the shape of the answer is that both are covered as generators.

**#16's second membership test, ruled here as routing's selection face.** Ring 0 is a standing routing result (§6) and its rows are lines, so *a field belongs in ring 0 iff, without it, the coordinator cannot decide where to look next* becomes: **a field belongs in ring 0's line if and only if, without it, the coordinator cannot decide whether to spend the next call.** Its content is #86's. #16's first test - *an observation earns its place iff a judgment demonstrably changes when it is present* - is the general form of which this is the instance for one judgment; it needs an observation to apply and stays at #16 with its wake unchanged.

### 5. The HNSW verdict - deliverable 4

**Scaffolding. Removed from #84's body.** The analogy failed on its subject, not on the two reservations the body recorded (random construction, distance metric): HNSW is an **index structure for similarity retrieval**, and what this system needed named is a **query model over typed edges**. Its descent story - enter sparse, go dense - describes the coordinator's *loop* (fetch, form an intent, resolve, fetch), which the session rejected as routing's definition; routing is one half of that loop.

**Replaced by a commitment: the skeleton is a property graph and routing is a traversal algebra over it.** Labelled nodes (`kind`), typed directed edges with a property (`locator`), and the four generators above map one-for-one onto a graph database's data model and traversal steps (`V(id)`, `V().hasLabel().has()`, `.out()/.in()`, `.repeat()`, `.not(out())`). `0059`'s persistence tier already holds the two primitives - *fetch-by-key and one-hop traversal* - unnamed. The commitment's value is that it states #84's asymmetry in one line: the write side is `addV / addE / property` (`0088`'s `set / attach / detach`), the read side is `V(id)` and no traversal.

**The commitment is bounded by the deviations, each of which is a ruling and none of which the commitment may override:**

| a graph database | this system | record |
|---|---|---|
| an edge requires both endpoints; delete cascades | a ref may dangle; nothing cascades | `0018` |
| an edge's identity is a surrogate; properties update | identity is the natural key with `locator`, for idempotent re-landing; no update, detach + attach; an `id` for addressing only | `0017` `0096` |
| schema optional or loose | link kinds a closed set with endpoint signatures; a compiler refuses | `0012` `0063` |
| membership is an edge | course membership is a field | `0029` |
| time on nodes | no time axis in the skeleton | `0021` |
| labels are flat | three semantic layers | `0009` `0027` |
| an engine with a planner | files plus an adjacency index rebuilt at load | `0062`, repaired in §9 |
| a vector index on the graph | two persisted things coupled by one field | `0019` |
| any caller, full depth | an observation contract: symmetry, discard, residency by policy | `0039` `0043` `0044` |

The last row is the boundary of the whole analogy: a graph database has no concept of what its caller may hold, and half of this repository's records are about that. The commitment covers the skeleton and routing; it does not cover the system. **Swapping in an engine is refused on this table**: an engine provides planning and transactions, which `0062`'s size and the single-writer contract do not need, and it requires the opposite of the first two rows.

### 6. What this makes ring 0

**Ring 0 is one standing routing result, held resident by policy.** The intent is, in outline, *obligation where 〈admission〉, select 〈the line's fields〉, order by `due`*. `0100`'s four clauses are that query's four parts: admission is its predicate, selection is its projection, arrangement is its order, refresh is re-running it. `0100` found that no clause was derived from the purpose because the purpose - this query - had no definition; **with routing defined the clauses are generated, not filled in**, and their content is #86's.

Why resident rather than re-run: spontaneity needs somewhere to stand when nothing has been fetched, and `0043` drops what is fetched, so the standing result must be held by **policy** - which is what `0019` already says ring 0 is. `0089`'s `refresh()` is that policy's re-execution. `0082`'s *obligation's line is ring 0's band* is not a field-set transfer; a ring 0 row **is** a line.

**`0021`'s time projection is another standing routing result** - *"a separate projection over the skeleton the way ring 0 is"* - so a projection is a result, not a layer, and **the layers are what routing ranges over**: the skeleton today, the store by #87's ruling. The body's fog patch on a below-skeleton layer waited on routing's output type; the output is lines and nothing in it is a layer entry, so a below-skeleton layer, if one exists, is something routing ranges over and its holder question is #66's unchanged. The patch dissolves into #66.

### 8. Findings that bind the sibling tickets

- **#86 (inputs).** Admission is the standing query's predicate and selection is its projection; both are now derivable and neither is decided here. Importance is not an input routing can carry - it is a judgment, not a capability - so *size* and *absorption* enter, if at all, as fields a line must carry for the spend-the-call decision, under the test in §4.
- **#87 (ownership).** The store is a layer routing may range over; a by-content intent is not in routing's domain by `0046`. So the question is narrower than the body states: not *who owns a store-reaching read* but *whether a by-handle read of the store is a routing generator, and who calls a by-query one*. S1 and S2 both reach the store only on their content half.
- **#88 (coverage).** `nodes_without` is the absence generator and `closure` is the transitive generator, signature for signature. The disposition available is not *covered / not covered* but *generator / separately named operation*. `0089`'s *"the read side is two verbs"* is audited by S3: `look_at` is fetch and `refresh()` is one frozen resolve, so the sentence was true and named nothing about resolve. `0084`'s composition of `obligations.list(course)` into `look_at(course)` is resolve entering through fetch - an instance, and the first leak the test would have caught.
- **#82 (ring 0's render).** Unblocked on the definition: a ring 0 row is a line, the standing query's parts are known, and what a render must carry is now stateable - *what lets the coordinator form its next intent*. The render's shape is not touched here.
- **#79 (tool descriptions).** Still blocked on #86-#88; the read side's list is now a generator set plus a composition rule rather than a verb list.
