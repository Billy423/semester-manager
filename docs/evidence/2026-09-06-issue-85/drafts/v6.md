### 1. Definition

**Routing is the resolving half of the query: a system-held function from an intent to the set of paths that satisfy it.**

```
routing : intent -> { path }
```

The query has two halves. **Fetch** takes an address and returns its render - `look_at(id)`, a read. **Resolve** takes an intent the caller can state in the skeleton's structural vocabulary and returns the paths that satisfy it, each ending at an address. Routing is resolve. Fetch may **compose** a resolve step into a render - `0084`'s `obligations.list(course)` inside `look_at(course)`, and the one-hop neighbourhood inside every block (`0096`) - which is resolve entering through fetch, ruled, and not fetch becoming routing.

**Who holds what.** The system holds routing, and holds by policy one standing intent whose result is ring 0 (§6). The coordinator holds the intent it forms and that one result resident. A dispatch target holds nothing (`CONTEXT.md`, *holder*). No new holder is introduced.

**Spontaneity, restated as a mechanism.** Routing is not prompt-driven, and *unprompted* does not mean *without the owner*: it means **the intent must be formable from the vocabulary plus what the current render exposes**. The vocabulary's closed sets - the kinds, the link kinds and their signatures (`0012`) - reach the coordinator out of band; by what carrier is #79's. Which of them apply *here* reaches it in-band: `0098` spells names back, `0092`'s `has-more` lists a node's link kinds, `0096`'s `<edge>` carries `type` and `direction`. So `look_at` is this system's introspection over a vocabulary the coordinator already has.

**What routing is not.** Not a search (`0046`: the coordinator *"does not search the corpus"*); not the delivery of an answer (that is fetch); not a judgment of importance (a judgment is made *with* operations and can never be an element of an operation set); not a statement about renders (what a render must carry so that an intent can be formed from it is stated here as a criterion, §4; what it looks like is downstream). Mechanistic reachability - that a path exists in the skeleton - is a property of the schema and not routing's; it is deliberately not universal, since two unrelated nodes may coexist.

### 2. Input - deliverable 1

**Routing's input is one intent, stated in the skeleton's structural vocabulary.** Not *ring 0 plus the skeleton index* as the body guessed - that is what the coordinator sees, not what routing consumes.

**The vocabulary.** A **node** is a kind, an id and that kind's field set, and `kind` is itself a field on the node (`0027`); a **layer** is one of three kinds and names the same set as that kind today; a field may be **Ref-typed**, naming another node (`0018`: `Ref := (kind, id)`, resolvable without a lookup); a **link** is its own record, `from · to · kind · role? · locator?` (`0017`), never a field on either end (`0016`); **link kinds** are a closed set with endpoint signatures (`0012`); **direction** is `points-at` or `pointed-by` (`0096`); an **annotation** is a node kind reached by an `about` link (`CONTEXT.md`). The vocabulary contains no set operations and no content.

**The intent's type, ruled.** An intent is a **chain**: a start, followed by steps, each of which either **filters** the current set by a predicate, **crosses** a relation the vocabulary names - a link kind in a direction, or a Ref-typed field in a direction - or **repeats** a crossing. A predicate ranges over the vocabulary - a member's fields, the relations it participates in, and **any earlier position on the path the member arrived by** - and may itself contain a chain from the member whose non-emptiness is the test (the join). A crossing from a member that has no such relation yields no path from it (`0046`: *"where no edge exists the walk returns nothing"*). Chaining is one call: each step's output is the next step's input. Set operations are not composition; they are not in the vocabulary. **The domain is bounded by this vocabulary, not derived from it**: which starts, crossings and predicate forms the grammar carries is decided by the judgments #86-#88 supply, under §4's test; §7 is the first application, over the judgments available today.

**An address** is a handle the query accepts: a node's `id`, and an edge's `id` since `0097` makes any tag carrying one addressable (`0089`'s *"`look_at(id)` reads one node"* predates `0096`; §9.5 amends it). Whether a chunk's handle is one is #87's.

**Outside the domain by type:** an intent by content. No predicate ranges over content, so *things about X* cannot be stated. Who serves such an intent, and with what, is #87's.

**A candidate step this vocabulary places but does not admit:** the store's by-handle read, *"the chunks a known node points at"* (`CONTEXT.md`). A chunk is not a node and the coupling is one field, `chunk.node_id` (`0019`), so it is a step onto the other persisted thing. Whether it enters routing's domain is #87's.

**Not decided here:** the grammar - which steps and predicate forms exist and how they are spelled (`0070`, `0093`, #84 *Destination*); the spelling of `points-at` / `pointed-by` once an intent names them back, which moves them out of `0098`'s *invented here → free* class (§9.5 amends `0098`; the spelling is #79's); whether an edge's `id` shares the node id space, which no record states.

### 3. Output - deliverable 2

**Routing returns a set of paths.** A path is the chain a member arrived by - node, relation, node, … - ending at an address, and the endpoint carries what decides whether it is worth the next call. A relation on a path is the link crossed, or the Ref-typed field crossed. Paths, not endpoints, because a judgment across obligations is a judgment about their **relations** (`0100` grounds the flat-render defect on `0001`'s second job, *"a statement about relations across obligations"*), and a set of endpoints has no position for a relation: obligations sharing a concept, as endpoints, is `{A, B, D}` with the pairing gone; as paths it is *A - requires → c - requires ← B* and the judgment can be made. **A path is simple** - no node appears on it twice - so the set is finite over any relation, cyclic or not. Deduplication is by path, so an artifact that `covers` a concept at two sections is two links (`0017`: `locator` is in the key) and two paths. A one-step chain's paths are the endpoints with the relation they were reached by; a start alone yields its members.

**Not bare ids.** An assigned id *"says nothing about the record it names"* (`CONTEXT.md`, `id`; `course.id` is supplied, `0026`), so an endpoint alone gives no basis to decide. Which fields decide the call for an obligation is the selection question, downstream (§6); for a `concept` or `artifact` endpoint the field set is the debt `CONTEXT.md`'s `the line` entry records against #17, #19 and #20.

**The set is symmetric.** Every endpoint carries the same deciding fields and no depth; where paths differ in length under a repeat, that asymmetry *"comes from the material"*, which `0039` calls legitimate. `0039`'s symmetry - the same observation for every member of the judgment's set - is met by the output type. Depth about any endpoint is fetch's, or dispatch's. **Affordability is a separate question the type does not answer**: a resolve over a whole kind, or a repeat over a cyclic relation, may be too wide to hold; what happens then - a narrower intent, a bound, or dispatch of the whole - is decided by no landed record: `0039`'s affordability is per-member depth (*"eight one-line summaries can be pulled for a comparison set, eight paragraphs cannot"*), and #12 item 6's bound is on free text, not on member count. It is open (§10).

**The set is unordered.** Arrangement is ring 0's own clause and is downstream (§6).

**The body's trichotomy is not three alternatives.** The output is a set of paths. *Dispatch* is the form `0039` selects when depth about a member is unaffordable. *Layer entry* is an intent over a different persisted thing, not a different kind of output. Nothing routing returns is an entry point into anything.

**An empty result names what it ranged over** - the kind, the source, the relation - so that a reader can tell *not in this range* from *not known*; `0081` requires a negative answer to name the boundary it speaks for, and a resolve's boundary is its range.

**Cost.** A start by ref and one crossing is O(degree) (`0046`); a start by kind is O(kind); a join costs one sub-chain per member. Ring 0's roughly-55 is one such result; it carries `0038`'s scope clause and the fall26 caveat.

### 4. The necessity test - deliverable 3

**The premise, ruled here.** A judgment ranges over a set, and **the set arrives in one return.** This is a direct ruling of this ticket, not a derivation, and it is stricter than either of its grounds alone: Billy's effectiveness constraint, recorded here for the first time - **the coordinator's call count may not grow with the graph** - and `0043`'s discard, under which what a return carried is dropped once used, so pieces of a set fetched separately do not survive to be joined. Effectiveness alone would permit a union of k fixed chains in k calls; the ruling does not, and the wildcard row in §7 rests on that. No landed record states this premise; it travels into the record §9.7 proposes. Whether dispatch calls count against the effectiveness constraint is not decided here.

> **A step or predicate form belongs in routing's domain if and only if some judgment the coordinator must make ranges over a set that no finite chain of the other steps and forms produces **exactly** in one return - where *other* excludes the one under test everywhere, inside a join included.**

**Standing of the test.** It is ruled as the instrument the sibling tickets apply. A finding at #86, #87 or #88 that the test admits what it should not, or excludes what it should not, revises the test and is recorded against it; the test is not a fixed point the findings must conform to.

**A stated limit.** The test admits by extension. Two spellings of the same set are one operation to it, and it must not be read as deciding that either spelling is absent from a surface; spelling is the grammar's. Under paths, a crossing and a join that tests the same crossing are not two spellings of one set: the first returns the relation, the second does not.

**#16's second membership test, ruled here as routing's criterion on a path's endpoint.** *A field belongs in ring 0 iff, without it, the coordinator cannot decide where to look next* becomes: **a field belongs on a routing result's endpoint if and only if, without it, the coordinator cannot form its next intent or cannot decide whether to spend the next call.** This is the criterion; which fields meet it for ring 0's rows is downstream (§6). **This departs from the body, which put both of #16's tests here.** #16's first test - *an observation earns its place iff a judgment demonstrably changes when it is present* - is the general form of which this is the instance for one judgment; it needs an observation to apply, which is #16's own wake condition, so it stays there unchanged.

### 5. The HNSW verdict - deliverable 4

**Scaffolding. Its descent story - enter sparse, go dense - describes the coordinator's loop (fetch, form an intent, resolve, fetch), which is not routing; routing is one half of that loop.

**Replaced by a commitment: the skeleton is a property graph and routing is a traversal over it.** §2's type maps onto a graph database's traversal model: a start is `V()` or `V(id)`, a filter is `.has()`, a join is `.where(__.…)` - a filter step carrying a sub-traversal - a crossing is `.outE(L).inV()`, a repeat is `.repeat()`, and the path output is `.path()`. `0059`'s persistence tier already holds *fetch-by-key and one-hop traversal*. The commitment's value is that it states #84's asymmetry in one line: the write side is `create / attach / set` (`0093`'s primitives); the read side is `V(id)` with one hop composed into it and no traversal as an operation.
