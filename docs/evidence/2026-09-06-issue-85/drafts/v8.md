### 1. Definition

**Routing is the resolving half of the query: a system-held function from an intent to the set of paths that satisfy it.**

```
routing : intent -> { path }
```

The query has two halves. **Fetch** takes an address and returns its render - `look_at(id)`, a read. **Resolve** takes an intent the caller can state in the skeleton's structural vocabulary and returns the paths that satisfy it, each ending at an address. Routing is resolve. Fetch may **compose** a resolve step into a render - `0084`'s `obligations.list(course)` inside `look_at(course)`, and the neighbourhood section `0094` places in every block - which is resolve entering through fetch, ruled, and not fetch becoming routing.

**Who holds what.** The system holds routing, and holds by policy one standing intent whose result is ring 0 (§6). The coordinator holds the intents it forms and that one result resident. A dispatch target holds nothing (`CONTEXT.md`, *holder*). No new holder is introduced.

**Spontaneity - ruled in the session.** Routing is not prompt-driven. *Unprompted* does not mean *without the owner*: it means **an intent must be formable from the vocabulary plus what the current render exposes**. The vocabulary - the current kind set, and the closed link-kind set with its signatures (`0012`) - reaches the coordinator out of band; by what carrier is #79's. Which of it applies *here* reaches the coordinator in-band: `0098` spells names back, `0092`'s `has-more` lists a row's link kinds wherever ring 0's render places it (#82), `0096`'s `<edge>` carries `type` and `direction`. So `look_at` is this system's introspection over a vocabulary the coordinator already has.

**What routing is not.** Not a search (`0046`: the coordinator *"does not search the corpus"*); not the delivery of an answer (that is fetch); not a judgment of importance (a judgment is made *with* operations and can never be an element of an operation set); not a statement about renders (what a render must carry so that an intent can be formed from it is stated here as a criterion, §4; what it looks like is downstream). Mechanistic reachability - that a path exists in the skeleton - is a property of the schema and not routing's; it is deliberately not universal, since two unrelated nodes may coexist.

### 2. Input - deliverable 1

**Routing's input is one intent, stated in the skeleton's structural vocabulary.** Not *ring 0 plus the skeleton index* as the body guessed - that is what the coordinator sees, not what routing consumes.

**The vocabulary.** A **node** is a kind, an id and that kind's field set, and `kind` is itself a field on the node (`0027`); the three layered kinds each name one layer, and `layer` is a different axis from `kind` (`0027`); a field may be **Ref-typed**, naming another node (`0018`: `Ref := (kind, id)`, resolvable without a lookup); a **link** is its own record, `from · to · kind · role? · locator?` (`0017`), never a field on either end (`0016`); **link kinds** are a closed set with endpoint signatures (`0012`); **direction** is `points-at` or `pointed-by` (`0096`); an **annotation** is a node kind reached by an `about` link (`CONTEXT.md`). The vocabulary contains no set operations and no content.

**What an intent is, ruled.** An intent is a **chain over the relations the vocabulary names** - the link kinds in their directions, and Ref-typed fields in either direction - with **predicates over the vocabulary that may join**: a predicate may itself contain a chain from the member it tests. Chaining is one call. Set operations are not composition; they are not in the vocabulary. **The domain is bounded by this vocabulary, not derived from it.** Which steps a chain may contain, what a chain carries from step to step, whether a crossing may be optional, what a predicate may reference on the path behind the member, and how any of it is spelled - all of that is the grammar, decided by the judgments #86-#88 supply under §4's test. §7 records the forms the first application used, as a draft.

**An address** is a handle fetch accepts: a node's `id`. Whether an edge's `id` is one - `0097` makes any tag carrying an `id` addressable, `0096` gave the edge its `id` so that `attach` and `detach` can name it, and `0089` says `look_at(id)` *"reads one node"* - turns on whether the two ids share one space, which `0025` scopes to *"every kind that can be a link endpoint"* and no record settles. Open (§10). Whether a chunk's handle is one is #87's.

**Outside the domain by type:** an intent by content. No predicate ranges over content, so *things about X* cannot be stated. Who serves such an intent, and with what, is #87's.

**A candidate step this vocabulary places but does not admit:** the store's by-handle read, *"the chunks a known node points at"* (`CONTEXT.md`). A chunk is not a node and the coupling is one field, `chunk.node_id` (`0019`), so it is a step onto the other persisted thing. Whether it enters routing's domain is #87's.

### 3. Output - deliverable 2

**Routing returns a set of paths, not a set of endpoints.** A path is the chain a member arrived by - node, relation, node, … - ending at an address, and the endpoint carries what decides whether it is worth the next call. Paths, because a judgment across obligations is a judgment about their **relations** (`0100` grounds the flat-render defect on `0001`'s second job, *"a statement about relations across obligations rather than about any one of them"*), and a set of endpoints has no position for a relation: obligations sharing a concept, as endpoints, is `{A, B, D}` with the pairing gone; as paths it is *A - requires → c - requires ← B* and the judgment can be made. **What a non-endpoint position carries, whether a path may repeat a node, how paths are deduplicated, and whether a crossing that finds no relation yields an empty position or drops the member** are the path's precise type, which is the grammar's; §7 records the choices the first application made and the two they left open.

**Not bare ids.** An assigned id *"says nothing about the record it names"* (`CONTEXT.md`, `id`; `course.id` is supplied, `0026`), so an endpoint alone gives no basis to decide. Which fields decide the call for an obligation is the selection question, downstream (§6); for a `concept` or `artifact` endpoint the field set is the debt `CONTEXT.md`'s `the line` entry records against #17, #19 and #20.

**The set is symmetric.** Each endpoint carries its own kind's deciding fields - one field set per kind, not varying per row (`0095`), kept on every row of a heterogeneous result (`0097`) - and no depth; where paths differ in shape, that asymmetry *"comes from the material"*, which `0039` calls legitimate. `0039`'s symmetry - the same observation for every member of the judgment's set - is met by the output type. Depth about any endpoint is fetch's, or dispatch's. **Affordability is a separate question the type does not answer**: a resolve over a whole kind, or a repeat, may be too wide to hold; what happens then is decided by no landed record - `0039`'s affordability is per-member depth (*"eight one-line summaries can be pulled for a comparison set, eight paragraphs cannot"*), and #12 item 6's bound is on free text, not on member count. Open (§10).

**The set is unordered.** Arrangement is ring 0's own clause and is downstream (§6).

**The body's trichotomy is not three alternatives.** The output is a set of paths. *Dispatch* is the form `0039` selects when depth about a member is unaffordable. *Layer entry* is an intent over a different persisted thing, not a different kind of output. Nothing routing returns is an entry point into anything.

**An empty result names what it ranged over** - the kind, the source, the relation - so that a reader can tell *not in this range* from *not known*; `0081` requires a negative answer to name the boundary it speaks for, and a resolve's boundary is its range. An intent the system cannot yet serve is **refused**, never returned empty (§5, `applies`).

**Cost.** A start by ref and one crossing is O(degree) (`0046`); a start by kind is O(kind); a join costs one sub-chain per member. Ring 0's roughly-55 is one such result; it carries `0038`'s scope clause and the fall26 caveat.

### 4. The necessity test - deliverable 3

**The premise, ruled here.** A judgment ranges over a set, and **the set arrives in one return.** This is a direct ruling of this ticket, not a derivation, and it is stricter than either of its grounds alone: Billy's effectiveness constraint, recorded here for the first time - **the coordinator's call count may not grow with the graph** - and `0043`'s discard, under which what a return carried is dropped once used, so pieces of a set fetched separately do not survive to be joined. Effectiveness alone would permit a union of k fixed chains in k calls; the ruling does not. No landed record states this premise; it travels into the record §9.7 proposes. Whether dispatch calls count against the effectiveness constraint is not decided here.

**The test, in its informal wording - ruled.**

> **A form belongs in routing's domain if and only if some judgment the coordinator must make ranges over a set that cannot be produced in one return without it.**

**Standing of the test.** It is ruled as the instrument the sibling tickets apply. A finding at #86, #87 or #88 that the test admits what it should not, or excludes what it should not, revises the test and is recorded against it; the test is not a fixed point the findings must conform to.

**Its formalisation is open, and is #86's first task before the test is run.** The first application (§7) exposed three questions the informal wording does not settle, and each changes verdicts: (i) *without it* - over which set of other forms, given that the set is what the test generates; (ii) *the set* - whether two chains produce the same set when their endpoints agree and their paths differ; (iii) *a form* - at what grain, given that `FILTER(P and Q)` and `FILTER(P) · FILTER(Q)` produce one set. The first application's provisional answers are in §7 and are not ruled.

**A stated limit.** The test admits by what a form lets a chain produce. Two spellings that produce the same thing are one form to it, and it must not be read as deciding that either spelling is absent from a surface; spelling is the grammar's.

**#16's second membership test, ruled here as routing's criterion on a path's endpoint.** *A field belongs in ring 0 iff, without it, the coordinator cannot decide where to look next* becomes: **a field belongs on a routing result's endpoint if and only if, without it, the coordinator cannot form its next intent or cannot decide whether to spend the next call.** This is the criterion; which fields meet it for ring 0's rows is downstream (§6). **This departs from the body, which put both of #16's tests here.** #16's first test - *an observation earns its place iff a judgment demonstrably changes when it is present* - is the general form of which this is the instance for one judgment; it needs an observation to apply, which is #16's own wake condition, so it stays there unchanged.

### 5. The HNSW verdict - deliverable 4

**Scaffolding. Removed from #84's body.** The analogy failed on its subject, not on the three reservations the body recorded - random construction, a distance metric, and `0046`'s bar on similarity: HNSW is an **index structure for similarity retrieval**, and what this system needed named is a **query model over typed links**. Its descent story - enter sparse, go dense - describes the coordinator's loop (fetch, form an intent, resolve, fetch), which is not routing; routing is one half of that loop.

The commitment's value is that it states #84's asymmetry in one line: the write side is `create · set · attach · detach · delete` (`0093`'s primitives); the read side is `V(id)` with one hop composed into it and no traversal as an operation.

### 7. DRAFT - the test's first application: its types, its forms, its gaps, and the gap table per scenario

**The precise types this application used, and what it left open.** A chain was taken to **carry paths** from step to step, each step acting on the path's endpoint, so that a predicate can reference an earlier position (`start.course`) and so that *the path a member arrived by* is a function. A path was taken to be **simple** - no node twice - so a repeat over a relation not ruled acyclic (`0012` rules only `part-of` a DAG) is finite; under that reading `closure` is the endpoint set of a repeat's simple paths, which matches `CONTEXT.md`'s *"set of nodes reachable"*. **Left open:** what a non-endpoint position carries - if only an id, *which concept* in job 2's judgment costs one `look_at` per intermediate, which §4's premise forbids; and whether a crossing may be **optional**, keeping a member that has no such relation with an empty position - without it, *what each obligation requires* returns only the obligations that require something, and the reader cannot tell *requires nothing recorded* from *out of range*, which is the silence `0081` and `CONTEXT.md`'s faithfulness axis forbid.

**Forms the application admitted:**

```

START(ref)               a spelling of START(K) · FILTER(id = X); the grammar keeps or drops it
FILTER(P)                keep the paths whose endpoint satisfies P
MOVE(L?, D?, Q?)         cross links of kind L in direction D; Q filters on the link's fields first;
                         L and D omitted means every kind, both directions
MOVE(field, D)           cross a Ref-typed field, either way
REPEAT(MOVE)             cross zero or more times

P ::= <field> <comparison> <value>  |  <field> <comparison> <position>.<field>
    | exists(chain)  |  not P  |  P and P  |  P or P
```
