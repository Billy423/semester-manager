# Inbound arrives to be known, not to trigger an action

Inbound does not arrive to trigger an action; it arrives to be known. The job is that when the user asks what a week was about, the system holds the surrounding context - not that it executes one operation per input, which is the model that had no correct branch for 55% of real announcements: room changes, section-scoped notices, pointers to portal paths and an accumulating strike count all needed to be known and none needed the system to do anything. The cost is taken knowingly: this is one step from a note pile, and the only thing keeping it a designed knowledge base is that the small typed layer stays populated.
